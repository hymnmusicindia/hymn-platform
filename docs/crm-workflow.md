# Contacts & Calls

Team OS now exposes Workspace and Management navigation. Contacts & Calls merges the former Acquisition CRM and Research & Acquisition entry points; old CRM links open the same screen. Other navigation sections are hidden without deleting their stored records. Overview, Calendar, projects, work, inbox, chat and the full Management section remain.

The main screen groups contacts visually into Research, Ready to call, In conversation, Interested, Converted and Closed. A separate call queue sorts scheduled follow-ups by time. Open a card to view attribution and source evidence, launch WhatsApp or the phone dialler, append notes, record actual contact evidence, link an existing customer and schedule the next call. All displayed/scheduled dates use Asia/Kolkata. A WhatsApp link requires a verified eligible contact and a phone including its country code; opening the link never records a contact event automatically.

Acquisition administrators set individual daily research/contact targets and explicitly choose rotation participants under each employee's target card. Only active, available participants with CRM view and outreach permission receive leads. New intake advances the rotation under the existing workspace transaction lock; researchers retain their original attribution. With no eligible caller, intake remains unassigned. Distribute unassigned contacts assigns the oldest eligible unassigned records in batches of 100. Target changes and assignment history are audited. Personal preference changes preserve these manager settings.

Research progress counts unique verified, unsuppressed contacts registered today. Contact progress counts distinct prospects with actual CONTACT events today, including existing outreach channels. Drafts and repeated contacts with the same prospect do not inflate the target. Non-administrators see their own progress. Targets use the existing member preferences JSON and require no new database migration.

Follow-up tasks appear in the existing calendar and My Work. Scheduling or changing a follow-up updates its active tasks; changing a task due time updates the contact schedule when the editor has outreach permission and access to that contact. A new scheduled lead receives a task immediately. Stage changes reuse the existing active follow-up rather than creating an extra task for every stage. Closed contacts cancel active follow-ups. Existing calendar task links open My Work to edit the time.

CRM stage changes and activity do not create earnings. Researcher/converter attribution remains separate. Customer linking, reconciled paid revenue, reward caps, holds, refunds, immutable earnings and payout controls retain the existing acquisition policy. Saving call evidence and contact changes uses a single transaction; a failed save rolls back the event as well.

The visual board displays the latest 100 authorised leads and filters those loaded records. Use Lead search, outreach & rewards for server-side searches, older records, CSV exports, employee tracking links, attribution review, email, reconciliation, payouts and policy settings. No external calendar sync, telephone provider or WhatsApp API is added; the links open the user's existing apps.

Design references: [Frappe lead List/Kanban views](https://docs.frappe.io/crm/lead), [Frappe assignment rules](https://docs.frappe.io/crm/assignment-rule), and [Pipedrive activities and linked next actions](https://support.pipedrive.com/en/article/activities).

Verification: `npm run test:acquisition` includes disposable-database CRM rotation, permission, deduplication, daily progress, scheduling and reward-separation checks. Build with the existing production command, then `npm run test:acquisition -- --browser` for desktop/mobile contact actions and existing finance regressions. `--build-browser` builds inside the disposable PostgreSQL fixture before running the browser checks, avoiding incompatible local database settings. A custom NEXT_DIST_DIR must match between the build and browser run.

## Daily employee programme

Owners supervise and approve work; they are excluded from target cards, caller rotation and new operational task/call assignments. Task creation, reassignment, calendar tasks, recurring-task creation and workflow rules enforce that boundary on the server, not just in dropdowns. Historical ownership and financial attribution are retained.

The configured programme assigns Tavish, Manha and Lavanya the Researcher role and 15 unique, verified, contactable leads each India calendar day. Kira has the Call Representative role and the combined call/email queue, with an editable 45-contact daily target. Researcher permissions cover intake and their own work; the representative has outreach permissions and cannot create researcher intake. No new platform-admin, payment or publishing rights are granted.

Daily tasks are created by the existing Team OS cron and on the first workspace visit each day, including a midnight check for open tabs. Workspace locking plus unique event keys prevent duplicate assignments. Deadlines are 23:59:59 Asia/Kolkata, every calendar day. Old incomplete assignments remain overdue instead of disappearing. Each employee also receives a one-time workflow preparation task.

Research targets count only unique leads registered that day with a verified, eligible source and a usable email/phone. Public-profile-only entries, drafts, suppressed contacts and duplicates do not count. Actual CONTACT events count distinct contacts for the representative. Progress completes daily assignments automatically. Employees cannot edit the programme's task target/ownership, claim completion before evidence meets the target, or cancel their own daily assignment. Administrators can cancel with a reason. A same-day quality correction can reopen a completed task if its verified progress falls below target. CRM activity still creates no financial reward by itself.

Researchers can correct their own saved phone/email, source evidence, eligibility and verification from the contact drawer without acquiring caller permissions. The server checks live ownership, version, duplicate contacts and existing accounts; suppressed/converted records cannot be repurposed through this action. Verification corrections update progress and can hand eligible saved research to the caller. Callers cannot edit researcher provenance or create researcher intake.

Verified contactable intake receives an available employee caller, Ready to contact status and a real follow-up task, even before its first appointment is scheduled. The call queue includes these unscheduled contacts. Daily sync also picks up contacts saved while the representative was away, preserving researcher attribution. No fictional contacts are seeded into the production CRM.

The Team Guide on Overview, My Work and Contacts & Calls provides role-specific next steps, live progress, open task links, intake/calendar shortcuts and guided answers about quality, handoffs, contact evidence and credits. It uses authenticated CRM data and curated workflow instructions; it does not send employee/customer information to an external AI service or require a new API key.

`scripts/configure-crm-programme.ts` previews the exact existing member IDs supplied by the operator. `--apply` checks the canonical production database and applies the programme in a single workspace-locked transaction. It does not invite accounts or infer membership by name. Superseded onboarding tasks and duplicate owner assignments are cancelled with audit history; unique operational owner tasks become employee research handoffs. No tasks or customer records are deleted. Existing payout/commission entries are unchanged.
