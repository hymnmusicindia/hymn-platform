# Team mobile workspace refresh

The native header keeps navigation, workspace identity, inbox and profile. Tapping the profile opens workspace details, theme switching, notification preferences, refresh, update checking and sign-out. Tools uses searchable, collapsed categories and only lists capabilities available to the signed-in member.

Complex workflows now open the complete existing Team OS screens inside the app using its authenticated session: contact cards, team email, projects, weekly hours, coordinator, reports, approvals, research, directory and authorized management. This reuses the existing forms, permission checks and validation instead of showing incomplete native summaries. Activity's full details open the existing task inside Team OS after saving the native draft. Returning refreshes the native activity. The native activity also exposes customer contact context, notes, needs, commitments, next action and a live elapsed timer derived from server timestamps. Paused and finished activities stop accumulating time.

Routine activity saves now post the known version once. The backend returns the accepted activity and incremented version; the app renders that response without a second read. On version conflict, it fetches and merges once using the existing conflict checks. Uncertain network writes are read back before retry, and local drafts remain available on failure. Changes show a local saved/syncing state before server confirmation. Other mutations preserve the current screen and show progress rather than replacing it with a full-screen loader. Targeted cache invalidation keeps unrelated projects and people screens warm; role/workspace scope, expiry, encrypted disk storage and authorization-failure clearing remain in place. Email delivery continues through the existing transactional outbox/background worker and is displayed as queued until delivered.

The embedded workspace only accepts the exact HTTPS HYMN origin for session-bearing navigation and downloads. It has no JavaScript/native bridge, no file URL access, no mixed content and no third-party cookies. Uploads use the system document picker; downloads require confirmation. Sign-out clears embedded cookies and web storage. Configuration follows [Android's WebView guidance](https://developer.android.com/develop/ui/views/layout/webapps/webview) and [file-access security guidance](https://developer.android.com/privacy-and-security/risks/webview-unsafe-file-inclusion).

Validation includes the Android APK build and unit tests for running/paused/finished timers, cache invalidation, workspace origin allowlisting, permissions, activity draft merge/conflict recovery and existing chat cache behavior. Isolated PostgreSQL workstation/call-report/leadership checks cover mobile contact privacy, accepted version responses, stale writes, concurrency, pause/resume, persistence, queued emails and deduplication. TypeScript checks cover the changed backend implementation. Device UI tests compile; the local Android emulator stayed offline, so they have not been executed on a working device in this run. No customer messages, calls or live team mutations are performed by these tests.
