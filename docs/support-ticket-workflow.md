Help & Support now collects a required reply email (prefilled from the account), optional UPC and up to three private JPG/PNG/WebP screenshots, 5 MB each. Existing service enquiry forms use the account email when no override is submitted. Screenshot ownership, file type and size are checked on the server; support reviewers require `services.manage` to view customer attachments and reply.

Customers can request a callback with an international phone number and a preferred time. This creates an internal Team OS follow-up for an available call representative, using the existing conflict-aware calendar scheduler. Preferred times are context for the representative, not automatic customer appointment confirmations. Ticket-specific numbers do not replace shared contact database numbers. If nobody is available, the request remains visible in support and is retried by the existing follow-up scanner.

Open Admin → Support → Open ticket to view attachments, record a real unanswered call or mark the customer contacted, and compose email. The solution template must contain actual steps before sending. Recording no answer unlocks a missed-call template asking the customer to reschedule from their ticket. Team OS call outcomes update the same ticket. Customers can see replies and callback state in their support history; email links open the corresponding ticket.

Emails enter a durable outbox. After-response processing and the `support-mail` cron claim queued messages atomically. Request keys prevent duplicate sends; missed-call messages are limited to one per recorded call attempt. Ambiguous delivery is held for review, with a deliberate retry requiring delivery-log inspection and a reason. Provider-accepted emails cannot be resent; interrupted attempts with a recorded acceptance reconcile to sent. SMTP must be configured and enabled; otherwise messages remain queued.

Deployment requires the additive `20261023210000_support_callbacks_and_replies` migration before application rollout, using the existing verified production migration command. No historical tickets are removed or rewritten.

Validation: `npm run test:support` applies the actual SQL to a disposable PostgreSQL baseline and exercises contact validation, screenshot ownership, callback assignment, outcomes/rescheduling, templates, concurrent outbox claims and delivery review with mocked email delivery. It does not send customer mail.
