# Website edge-case audit — 4 November 2026

This audit covered customer, distribution, billing, referral, studio, team and download workflows. Tests used isolated databases and mocked payment, distribution and email transports. Production public pages were checked with read-only HTTP requests. No real customer charge, payout, release submission or customer email was generated by this audit.

## Product fixes

| Finding | Change | Verification |
| --- | --- | --- |
| Android download page used fixed dark colours and a gold download action, overriding HYMN's active theme. | Page surfaces, borders, text, download action and copy-link control now use the shared theme tokens. | Actual page/component browser fixture at 320, 390 and 1440 px in light and dark themes; version, copy feedback, links and overflow checked. Shared palette contrast contract passed. |
| Team OTP sign-in checked body length only after reading the entire request, and counted characters rather than UTF-8 bytes. | Read a bounded stream, stop at 4096 bytes and return 413 for oversized input; malformed JSON/UTF-8 returns 400. | Exact boundary, missing/oversized Content-Length, streamed requests, cancellation, multibyte characters and split Unicode tests. Team OTP integration tests also passed. |
| Production origin selection could accept IPv6 loopback or a trailing-dot localhost as its public URL. | Normalize hostname brackets and trailing dots before rejecting local production origins. | IPv4, IPv6, expanded IPv6, localhost, trailing-dot local hosts, configured public origin and development-origin tests. |
| Draft and artist endpoints accepted numeric coercion or IDs beyond the database integer range. | Share strict positive decimal PostgreSQL ID validation across draft reads/saves, artist updates/deletion and release deletion. | Invalid, negative, fractional, exponent, hexadecimal, whitespace and overflow IDs rejected before draft database queries. Authentication remains mandatory. |
| Draft autosave treated malformed JSON as an empty object, and null/array bodies could fail unexpectedly. | Return a validation response instead of entering the save transaction. Bound draft JSON to 2 MiB while streaming. | Actual route tests verify invalid inputs never enter a mutation and valid drafts remain readable. |
| Draft metadata could be an array, scalar or null rather than an object. | Reject malformed metadata with 400 before saving. | Null, array and string metadata regression cases. |

## Test-system repairs

- `npm test` now passes the required React server condition to its child processes. Previously the command could stop on a `server-only` import before reaching the remaining suites. All 15 existing core groups now pass.
- Updated obsolete assertions to match current accepted-attempt polling, approved producer/admin storefront accounts, mandatory curator settlement amounts, always-visible keyboard-accessible playback controls and the artwork-card catalogue.
- The customer browser audit now waits for the audio-library redirect before inspecting the destination.
- The licence upload test now opens the rights section in the single scrolling sheet instead of looking for the retired standalone review screen.
- The library fixture now provides the storage usage data required by the current component.
- Added a lightweight subscription browser harness that runs the existing interaction test against the real components and styles without compiling the entire application.

The beat-store artwork grid was inspected and preserved. No beat-store redesign was shipped as part of this audit.

## Dependency security fixes

The runtime dependency scan initially reported **19 advisories: 1 critical, 10 high and 8 moderate**. After patching, the clean production lockfile scan reports **8 moderate, 0 high and 0 critical**.

- Updated Next.js to **16.4.5** and its ESLint configuration to the matching version, following the [official framework security advisories](https://github.com/vercel/next.js/security).
- Updated Axios to **1.21.0**, Sharp to **0.35.5**, Nodemailer to **10.3.1**, source-map-js to **1.2.2** and follow-redirects to **1.16.2**.
- Patched brace-expansion to **1.1.21 / 2.1.7** on the applicable dependency branches. Refreshed a stale lock entry using the registry's exact version, tarball URL and integrity hash.
- Patched deepmerge-ts to **8.0.2**, retaining Prisma **6.19.3**. Prisma schema/config validation passed; no database migration or Prisma downgrade was performed.
- Migrated Zod to **4.6.7**, adapting record schemas and licence-consent error customization using its [official migration guide](https://zod.dev/v4/changelog). Explicitly removed creation defaults from partial artist/task update schemas so changing one field cannot reset producer flags, task priority, approval requirements, dependencies or checklists. Added regression tests for omitted versus explicitly cleared fields.

The core and financial regression suites were rerun against the patched dependencies. New request/update regressions now run automatically through `npm test`.

## Passed checks

- **15 core regression groups:** performance architecture, first-release promotion, artist profiles, integration contract/failure matrix, producer/contributor identity, analytics, migration safety, payment signatures, subscriptions, payment enforcement, storage/media integrity, release states/identifiers, payouts and services.
- **Referral/payment integration:** 58,824 rounding and commission-cap scenarios, network rewards, duplicate and circular attribution, eligibility, cooling periods, concurrent approval, full/partial/duplicate refunds, stale revenue evidence, Gmail-alias self-referrals, payout reservations, duplicate bank references and webhook replay.
- **Studio integration:** quote/payment idempotency, acceptance, included and paid revisions, deliveries, settlements, release handoff, chunked upload checksums/resume/replay, access boundaries, ranged reads, dispute holds and late capture/refund recovery.
- **Team OTP integration:** expiry, tampering, replay, concurrent redemption, attempt limits, revoked/banned memberships, origin checks and account privacy.
- **Browser fixtures:** beat playback and licensing; library search/pagination/downloads; call timers, autosave and closure; call reports; permission-aware assistance; release sheet/navigation/review popup; correction licence upload retry; distribution catalogue; subscriptions; Android download theme/copy links. Responsive checks included 320 px where supported and light/dark themes in the relevant suites.
- **Live public HTTP checks:** all 18 sampled routes returned nonempty HTTP 200 responses, including home, beat store, distribution, studio, services, contact, FAQ, login, app pages, onboarding, referrals, policies, sitemap and robots.
- **Customer-page browser sampling:** 16 routes passed desktop and mobile checks, producing 32 successful views without recorded render/API errors, broken images, unnamed controls or horizontal overflow.

## Limits and remaining verification

This is broad regression coverage, not proof that every possible interaction on the website is defect-free. The full authenticated page sweep hit the local machine's memory limit during development compilation. Purchase/support full-page checks and the remaining role/page sweep were therefore not certified by that run. Smaller library, support/access, team and service fixtures supplied additional coverage, but do not replace every full-page integration scenario.

Real payment settlement, inbox delivery, partner ingestion and installation on physical devices were not exercised during this audit. Existing production customer records were not modified.

**Outstanding dependency work:** eight moderate advisories remain in the legacy ExcelJS/archive chain: archiver, archiver-utils, exceljs, glob, minimatch, readdir-glob, rimraf and zip-stream. This needs a compatible spreadsheet/archive migration and import/export regression coverage. The dependency scan is therefore not completely clean.
