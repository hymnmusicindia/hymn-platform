# Admin navigation and Team Chat responsiveness

Admin query-tab links on `/admin` now use Next's supported native History integration: immediate local switching, retained page state, and browser back/forward without repeating the server-page database queries. Separate admin routes keep normal navigation, with hover/focus prefetch and an admin loading boundary. APIs retain live authorisation; this does not cache privileged responses across sessions or grant extra permissions.

Team Chat uses optimistic message bubbles, server-confirmed Sent status, per-conversation drafts, explicit failed/retry states, and the same UUID on retries for database-backed deduplication. Sending no longer refreshes unrelated workspace data. Desktop Enter sends, Shift+Enter inserts a newline; touch devices retain multiline Enter and a Send button.

Server-sent events renew roughly every 24 seconds. Each active stream checks the authenticated account, workspace membership, permissions and channel access against the database every 1.2 seconds. This bounded database-backed transport works across Node workers and requires no Redis or external realtime account; it is near-real-time, not a guarantee of WhatsApp-scale latency. On transport errors, a non-overlapping three-second fallback fetch is used; background tabs disconnect and focus/reconnect rehydrates the latest 50 messages. No offline persistence of message content is added. Proxies must support SSE without buffering; fallback remains available otherwise.

Read receipts reuse the existing `readMemberIds` field—no migration. The client batches only messages intersecting the chat viewport while the document is visible and focused. Writes are authenticated, same-origin, channel-scoped and deduplicated under the existing transaction lock. Reader photos/names are restricted to active participants in that workspace/channel; absent photos use initials. Sent means saved by the server, not seen. Existing threaded-message tools remain available separately. This release changes Team Chat, not Studio order or referral chat.

Research: [Next navigation and native History](https://nextjs.org/docs/app/getting-started/linking-and-navigating), [prefetching](https://nextjs.org/docs/app/guides/prefetching), and [Socket.IO delivery guarantees](https://socket.io/docs/v4/delivery-guarantees/) informed local transitions, reconnect synchronisation and durable idempotency. No Socket.IO dependency was needed.

Verification: `node --import tsx scripts/verify-team-os-isolated.ts --live-chat` covers core authority regressions plus a two-user browser test for optimistic sends, streamed messages, avatar receipts, failed-send retries, private-channel access, mobile layout and zero server-page requests during admin tab changes.
