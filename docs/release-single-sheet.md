# Scrolling release editor

The two opening screens are retained for a new release: mandatory artist selection (saved through the existing artist/draft handler), followed by optional initial audio upload. Skipping audio only skips that opening screen; the existing final audio validation remains required. Existing artist-bound drafts and amendments open the sheet directly. The opening screens are not navigation destinations in the sheet.

The remaining editor is one persistent sheet: tracklist, cover art, release information, then ownership, rights and delivery. Already-released UPC and per-track ISRC controls live in Tracklist. The cover preview has a visible inset border. Existing section content, field state, upload handlers, draft autosave/version checks and payload construction are reused. The track audio controls reuse the existing upload/replacement actions, so skipped audio and later replacements remain accessible without reopening the initial screens.

The blurred section carousel stays above the sheet. Its current item follows scroll position within the window or an ancestor scroll container. Selecting a section scrolls to its existing anchor; it does not unmount fields, start a submission, change input values or restart section animations. Existing stage identifiers are retained for draft resume and analytics. Reduced motion disables animated navigation. Validation focuses the actual field, including audio and artist fields in the track card and rights fields in Delivery.

The sticky carousel measures the actual sticky site-header height (including mobile subheader) and observes size changes, keeping navigation and actions below that header instead of behind it. A prominent Review release button beside Draft at the bottom uses the same validation and review action as the top toolbar. It is a non-submit button; actual submission remains in the review dialog and still requires the existing final confirmation. Browser checks include an overlapping site-header fixture, resizing its height while scrolled, visibility/hit testing throughout the sheet, and the bottom review action.

Review uses the existing release summary, pricing and submit handler in an accessible letter-style overlay. It has a close control, Escape and focus trapping. Edit actions close the popup and scroll to the correct editor section after focus restoration. Its native submit button explicitly associates with the existing form. The separate final confirmation remains required and can return to review; payment/submission requests occur only through the existing handlers. Background scroll is locked during dialogs.

Missing-field feedback appears at the corresponding control, with red styling, associated error text and focus on the first relevant field. Resolved errors clear without discarding input. Review exposes all current missing fields; operational upload/network errors remain separate. Client genre/subgenre and release-language checks use the same provider taxonomy as backend preflight.

Previous-release suggestions use a compact disclosure with source and current-value context. Bulk confirmation only accepts matching, valid, non-rights suggestions. Manually edited values are preserved; ownership suggestions require individual decisions. Changing genre clears an incompatible subgenre. Read-only plan labels cannot be overwritten. This follows [GOV.UK contextual error guidance](https://design-system.service.gov.uk/components/error-message/) and [NN/g guidance on simplifying forms and editable reused values](https://www.nngroup.com/articles/eas-framework-simplify-forms/).

Verification: `scripts/verify-release-sheet-browser.cjs` renders the actual form inside the existing portal shell at 1440, 768, 390 and 320 pixels in light and dark themes. It verifies section order, cover border, persistent sections, scroll-synced navigation, sticky header visibility, review popup, Escape/edit return, final confirmation and return-to-review, native form association, and no accidental submission/checkout requests. Mobile opening-screen scenarios verify required artist selection, saving before audio, skipping initial audio, no repeated opening panels and final audio validation. `scripts/verify-release-ux-edgecases-browser.cjs` covers 36 scenarios across light/dark desktop and mobile: missing fields, edited suggestions, instrumental tracks, prior-release identifiers, non-exclusive licences, and invalid legacy taxonomy. `scripts/verify-release-prefill-review.ts` checks safe confirmation policy. Existing provider-contract, pricing and first-release suites pass. Scoped TypeScript checks cover the form and imported components. No production customer submission, payment or email is used for these checks.
