# Scrolling release editor

The two opening screens are retained for a new release: mandatory artist selection (saved through the existing artist/draft handler), followed by optional initial audio upload. Skipping audio only skips that opening screen; the existing final audio validation remains required. Existing artist-bound drafts and amendments open the sheet directly. The opening screens are not navigation destinations in the sheet.

The remaining editor is one persistent sheet: release information, cover art, tracks and credits, then rights and delivery. Existing section content, field state, upload handlers, draft autosave/version checks and payload construction are reused. The track audio controls reuse the existing upload/replacement actions, so skipped audio and later replacements remain accessible without reopening the initial screens.

The blurred section carousel stays above the sheet. Its current item follows scroll position within the window or an ancestor scroll container. Selecting a section scrolls to its existing anchor; it does not unmount fields, start a submission, change input values or restart section animations. Existing stage identifiers are retained for draft resume and analytics. Reduced motion disables animated navigation. Validation focuses the actual field, including audio and artist fields in the track card and rights fields in Delivery.

Review uses the existing release summary, pricing and submit handler in an accessible letter-style overlay. It has a close control, Escape and focus trapping. Edit actions close the popup and scroll to the correct editor section after focus restoration. Its native submit button explicitly associates with the existing form. The separate final confirmation remains required and can return to review; payment/submission requests occur only through the existing handlers. Background scroll is locked during dialogs.

Verification: `scripts/verify-release-sheet-browser.cjs` renders the actual form inside the existing portal shell at 1440, 768, 390 and 320 pixels in light and dark themes. It verifies persistent sections, scroll-synced navigation, sticky header visibility, review popup, Escape/edit return, final confirmation and return-to-review, native form association, and no accidental submission/checkout requests. Mobile opening-screen scenarios verify required artist selection, saving before audio, skipping initial audio, no repeated opening panels and final audio validation. Existing pricing, first-release and store-catalogue suites pass. Scoped TypeScript checks cover the form and imported dialogs/hooks. Twelve existing upload, payload, payment and submission functions were compared against the previous commit and are semantically unchanged. No production customer submission, payment or email is used for these checks.
