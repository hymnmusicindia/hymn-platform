# Admin Users and manual subscriptions

Active subscription entitlement now excludes an account from FIRST_RELEASE_FREE, whether manually granted or provider-paid. Both eligibility and reservation enforce this server-side; drafts saved with the old campaign do not override an active plan in the release form. The subscriber-facing offer page explains plan coverage instead of falsely claiming the gift was redeemed. Draft reminders inherit the same eligibility rule. Expired/cancelled subscriptions without submitted releases can qualify again; this rule targets currently subscribed accounts.

Manual grants explicitly include unlimited releases, plan-specific artist capacity and no automatic billing. Legacy manual grants with null releaseLimit and ["all"] features are honoured as unlimited. This does not change provider subscription quotas. Extend adds days to the existing term on the same plan; replace starts a new term immediately. Usage and financial history are retained. Active provider billing cannot be overwritten by a manual grant. Previously cancelled provider references and stale renewal/period fields are cleared on a new manual grant. Mutations require recent permission-checked administrator authentication, same-origin requests and reasons. Grants/revocations reject stale versions. Manual grant and audit records commit together. Checkout credit requests use a stable per-request UUID and an atomic ledger/audit write to prevent duplicate credits on retry.

The user directory has name/email/ID/role search, account filters and profile photos with initials fallback. Account details open in a native modal side drawer with keyboard trapping, Escape dismissal, mobile full-width layout and filter retention. Releases/drafts, support, purchases/payouts, activity, account facts, subscription/credits and sensitive flags/access controls remain permission-gated. Specialist release inspection links still open their existing admin module; account inspection itself never leaves the directory. No new schema migration.

Verification: `node --import tsx scripts/verify-manual-subscriptions-isolated.ts --browser`. This uses an isolated local database, fixture users and local Next server. It must never run with production database URLs. Real provider cancellation is not exercised by the fixture; production billing remains the existing provider management flow.
